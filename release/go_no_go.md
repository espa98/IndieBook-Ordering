# 릴리스 Go / No-Go (10단계)

작성일: 2026-11-24 (갱신) · 기준 커밋: 최신(테스트 129 files / 1265 tests 통과, 마이그레이션 001~021)

## 결정: **NO-GO**

`ordering-dev` 적용과 운영 배포는 모두 **금지**한다. 격리 DB에서 모든 테스트가 통과하더라도 `ordering-dev` 적용과 운영 배포는 **별도의 사용자 승인 전에는 하지 않는다**(공통 안전규칙). 이 판정은 승인 요청이 아니라 현재 상태의 판정이다.

## 2. 기능 범위 차단 조건

10단계 이후 도메인 로직이 추가되어 아래 항목은 **해소(PARTIAL 이상)** 되었다: 전량 취소·취소 종결(ST-O06/O08), 수령 정정(ST-F02), 공급처 발주 외부 의무와 종결 차단(BR-P05/P06), 환급 실패·UNKNOWN(ST-Y07), 조달 배정 해제·미전달 발주 취소(ST-P02/P09), 발주 종결(ST-P11). 모두 PARTIAL이며 한계는 `testing/test_matrix.csv`에 있다.

P0인데 **여전히 미구현**인 항목: 인증·테넌트(ST-A06/A07 중지·해지 미구현. A01~A05는 PARTIAL), 도서·공급처·템플릿 관리 외부 연동(ST-B01 YES24 검색은 연동 없음, 도메인 로직은 PARTIAL). 주문 보류(ST-O02)·가격/품목 변경(ST-O04, DEC-08 승인 전)·초안 폐기(ST-O09)도 미구현이다.

### 2.1 명령 영속화 현황 (기계적으로 센 값)

`authorizedActions`에 바인딩된 도메인 명령 70개 중 **55개를 어댑터(`src/db/pg*Api.ts`)가 직접 실행**하고, 5개(`deliverAllocation`·`deliverStockReservation`은 수령 경로, `confirmRefund`는 환급 승인 경로, `getOrder`·`listOrders`는 읽기 경로)는 그 명령을 통해 간접 실행되어 **60개가 영속화**되었다. **10개는 아직 영속화되지 않았다**(그 명령은 메모리 저장소 도메인 테스트로만 검증된다):

| 영역 | 영속화되지 않은 명령 | 영향 |
|---|---|---|
| 결제 | `reportRefundAttempt`·`resolveRefundAttempt`(환급 시도 실패·UNKNOWN) | 환급 도중 실패·UNKNOWN을 처리할 수 없다. (재고 등록·조정·예약 해제와 결제 무효는 §36에서 영속화했다) |
| 직원·인증 | (초대·철회·비활성화는 §37에서 영속화) 남은 것: **초대 수락**(`acceptInvitation`), 서점 개설(`openStore`), 계정 등록·이메일 인증 | 직원이 초대를 수락해 멤버가 되는 경로가 없다(멤버는 SQL로만 추가). 수락은 JWT의 이메일 claim 신뢰 범위 결정이 필요하다(E3 후속) |
| 도서·템플릿 | (도서 등록·수정은 §38에서 영속화) 남은 것: `publishTemplateVersion` | 안내 문구 템플릿 게시 불가. YES24 검색 연동은 없어 도서는 수기 또는 호출자가 보낸 YES24 결과로만 등록된다 |
| 고객 안내 | `createNotificationTarget`·`recordNotificationAttempt`·`recordNotificationCopy`·`recordNotificationResult`·`renotify` | 안내(알림) 전체가 영속화되지 않음. `longUnreceivedWarnings`도 마찬가지 |
| 서비스 주문 | `createOrderService`·`confirmOrderService` | 서비스 주문 경로 없음(일반 주문은 `createOrder`·`confirmOrder`로 영속화됨) |
| 기타 | 발주 CSV 출력 이력(`exportPurchaseOrderCsv`, 바인딩 없음) | 전달 기록의 `fileVersion`을 지정하면 거부된다 |

위 표가 **다음 구현 우선순위의 근거**다. 남은 것 중 **초대 수락·서점 개설**(E3 후속 결정 필요), 환급 시도 실패 처리가 운영 시작에 필수인 P0 흐름이다.

추가 차단·주의(10단계 이후): 새 검사 중 일부는 선택 의존성을 서버 조립에서 연결해야 동작한다(`testing/acceptance_report.md` §9.1). **현재 어댑터 연결 상태:** `allocateSourcing`·주문 종결·주문 재개의 `supplierObligations`(BR-P05), 재개의 `fulfillmentCorrections`, 환급 요청의 `refundAttempts`·`refundAttemptResolutions` 조회, 주문 생성의 `books`는 연결되었다. 환급 **시도 기록 명령**(`reportRefundAttempt`·`resolveRefundAttempt`)은 영속화되지 않아 시도 기록은 항상 비어 있다. 연결 누락을 배포 전 점검 항목에 넣어야 한다.

## 1. 향후 DB 적용 시 원칙

공통 안전규칙을 따른다: **확장 → 백필 → 검증 → 전환 → 정리**. 파괴적 `DROP/DELETE/REVOKE`는 영향 분석과 별도 승인 전에는 실행하지 않는다. 레거시 RPC(`ordering_v2_command`, `ordering_request_approval`, `ordering_decide_approval`, `ordering_v2_refund_confirm`)는 신규 API가 준비되기 전에는 변경하지 않는다.

| 단계 | 되돌릴 수 있는가 | 롤백 방법(계획) |
|---|---|---|
| 확장(Expand): 새 테이블·컬럼·함수 추가 | 예(추가만 한 경우) | 새 객체 제거. 기존 객체는 건드리지 않음 |
| 백필(Backfill) | 부분 | 백필 대상에 원본 보존 컬럼 유지, 롤백 시 신규 컬럼 비우기. 백필 전 스냅샷 필수 |
| 검증(Verify) | 해당 없음 | 검증 실패 시 전환 중단 |
| 전환(Switch): 신규 경로 사용 | 예(전환 스위치가 있을 때) | 기능 플래그/라우팅으로 레거시 경로 복귀. 전환 시 레거시 경로를 끄지 않음 |
| 정리(Contract): 레거시 제거 | **아니오** | 별도 승인과 백업 후에만. 이 단계는 롤백이 아닌 복구(백업 복원)에 의존 |

## 2. 적용 전 필수 준비(미준비)

- 격리 DB에서 모든 마이그레이션의 정방향·역방향을 먼저 실행해 검증. **미수행.**
- 적용 직전 스냅샷(백업)과 복원 절차 리허설. **미수행.**
- 데이터 변경(백필·원장 기록)의 영향 범위와 되돌림 불가 항목 목록. **미작성.**
- 외부로 나간 사실(안내 발송, 반품 출고, 결제·환급 증빙)은 시스템 롤백으로 되돌릴 수 없고 **보정 기록**으로 정정해야 한다(원장은 추가 전용). 이 정책은 도메인 코드에 반영되어 있다(정정은 원거래 참조 역거래).

## 3. 롤백 트리거(제안)

- 원장 불변식 위반(예: 입고 버킷 합계 불일치, 환급 합계가 원 결제 초과)이 대사에서 발견됨.
- 교차 tenant 노출 또는 권한 우회 징후.
- 종결·환급·인도 같은 민감 명령의 비정상 중복 실행.

트리거 발생 시: 1) 신규 경로 스위치 차단, 2) 레거시 경로 복귀, 3) 영향 범위 대사, 4) 보정 기록 또는 백업 복원 중 승인된 방식 실행. 각 단계의 담당과 승인자는 미정이다.

## 4. 알려진 롤백 불가·위험 항목

- 이미 기록된 외부 사실(안내 시도·결과, 반품 출고, 환급 완료 증빙)은 삭제하지 않고 정정 기록으로 처리한다.
- 감사 로그가 구현되지 않아(T9) 롤백 시 "누가 무엇을 했는지" 재구성 근거가 도메인 기록에만 있다.
- 원자 롤백이 구현되지 않아(T4) 부분 실패 시 수작업 정리가 필요할 수 있다.

## 5. 이 계획의 한계

실행·리허설되지 않았고, DB·배포 환경이 없어 구체적 명령·스크립트·소요 시간·담당자를 적지 못했다. 격리 DB와 마이그레이션 초안이 생긴 뒤 구체화해야 한다.

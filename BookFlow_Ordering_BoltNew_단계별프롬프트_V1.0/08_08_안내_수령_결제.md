## 이번 단계의 실행 지시
(추가) 안내 대기열(`GET /notification-targets`)의 각 항목에는 주문에 연결된 고객이 있으면 `customer`(이름·전화번호 전체)가 실린다 — 직원이 전화로 안내할 수 있도록 보여 준다(없으면 "연결된 고객 없음"). 번호는 필요한 화면에서만 노출하고 목록 캐시·로그에 남기지 않는다.

O-08/08-01~04, O-09/09-01~06을 구현한다. 확보 안내 기본은 전체 확보, 부분 안내는 직원 선택. 메시지 템플릿/미리보기/복사·공유/실제 발송 결과 입력을 분리하고 복사만으로 발송 완료 금지. 수령은 확보된 미인도량 및 취소 대기 잠금을 검증, 인도 전 해당 금액 결제 확인(후불 기본 금지). 결제는 카드/간편결제/계좌이체만, P0 실제 외부에서 확인한 거래의 수동 사실 기록만; 앱에서 결제 승인/PG 처리하지 않는다. 복수 외부 확인 거래 최소 기록 및 과수납 환급 필요 업무 표시. 결제/환급의 외부 증빙이 불충분하면 완료 표시 금지. 테스트: 부분 수령, 미확인 결제, 복사만 한 안내, 중복 결제 참조, 인도·취소 경쟁.

## 작업 방법
1. 현행 코드와 참조 문서의 화면 ID/필드/규칙/우선순위를 대조하고 구현 목록을 작성한다.
2. 기존 구현을 보존하면서 컴포넌트·라우트·폼·검증·오류 상태를 구현한다. 화면마다 로딩/빈 상태/오류/권한 없음/재시도 UI를 포함한다.
3. API가 실검증되지 않았으면 `DEMO MODE` 또는 비활성 기능으로 구분한다. 백엔드/DB를 임의 변경하지 않는다.
4. 가능한 테스트를 실행하고 실패한 항목은 수정하거나 근거와 함께 미완료로 보고한다.
5. 화면 ID별 변경 파일, 실제 API 연결 여부, 테스트 결과, 정책 게이트, 다음 단계 진행 조건을 한국어로 요약한 뒤 멈춘다.

## 완료 기준
- 문서에 정의된 P0 화면 동작과 오류 상태가 확인된다.
- 미승인 정책은 활성화되지 않는다.
- 테스트되지 않은 API를 성공 처리하지 않는다.
- 이전 화면/데이터의 회귀 오류가 없다.

# 01단계 — 프로젝트 구조와 공통 UI

## Bolt.new에 붙여넣을 프롬프트

당신은 BookFlow Ordering의 웹 프런트엔드 개발자다. 먼저 `00_공통_실행규칙.md`를 적용하고, 아래 파일을 실제로 읽어라.

참조 문서: Docs/03_UI_UX/Ordering_IA_V1.3_OPDS_V1.1_동기화.md; Docs/03_UI_UX/Ordering_WebP0_Wireframe_UIUX_Guide_V1.1_비판적검토_개선본.md

## 이번 단계의 실행 지시
현재 저장소의 프레임워크, 라우터, 인증, 컴포넌트, API 클라이언트, 환경변수와 기존 페이지를 읽기 전용으로 진단한다. 미존재 시 React+TypeScript, 재사용 가능한 폴더 구조와 라우팅을 구성한다. IA §2의 웹 메뉴 10개(대시보드, 주문, 발주·공급처, 입고, 도서·재고, 고객, 안내, 수령·결제, 반품·정정, 설정), 상단 서점 선택·계정, 좌측 내비게이션, 모바일 접힘 메뉴를 만든다. UI/UX 가이드 §5~7의 디자인 토큰·버튼·폼·상태·접근성 규칙을 파일로 분리한다. G-01/G-02 공통 오류·빈 결과·오프라인·충돌 컴포넌트를 만든다. 각 메뉴는 빈 껍데기 대신 해당 화면의 구현 예정 상태를 명시한다. 테스트: 라우트 접근, 모바일 360px, 키보드 포커스, 콘솔 오류 없음.

## 작업 방법
1. 현행 코드와 참조 문서의 화면 ID/필드/규칙/우선순위를 대조하고 구현 목록을 작성한다.
2. 기존 구현을 보존하면서 컴포넌트·라우트·폼·검증·오류 상태를 구현한다. 화면마다 로딩/빈 상태/오류/권한 없음/재시도 UI를 포함한다.
3. API가 실검증되지 않았으면 `DEMO MODE` 또는 비활성 기능으로 구분한다. 백엔드/DB를 임의 변경하지 않는다.
4. 가능한 테스트를 실행하고 실패한 항목은 수정하거나 근거와 함께 미완료로 보고한다.
5. 화면 ID별 변경 파일, 실제 API 연결 여부, 테스트 결과, 정책 게이트, 다음 단계 진행 조건을 한국어로 요약한 뒤 멈춘다.

## 완료 기준
- 문서에 정의된 P0 화면 동작과 오류 상태가 확인된다.
- 미승인 정책은 활성화되지 않는다.
- 테스트되지 않은 API를 성공 처리하지 않는다.
- 이전 화면/데이터의 회귀 오류가 없다.

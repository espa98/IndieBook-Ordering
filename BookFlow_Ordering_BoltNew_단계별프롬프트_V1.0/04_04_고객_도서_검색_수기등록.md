# 04단계 — 고객 및 도서 기준정보

당신은 BookFlow Ordering의 웹 프런트엔드 개발자다. 먼저 `00_공통_실행규칙.md`를 적용하고, 아래 파일을 실제로 읽어라.

참조 문서: Docs/01_Requirements/Ordering_FRD_V1.3_OPDS_V1.1_동기화.md; Docs/03_UI_UX/Ordering_IA_V1.3_OPDS_V1.1_동기화.md

## 이번 단계의 실행 지시
C-01~04, B-01~05 화면을 구현한다. 고객 검색/등록/중복 후보 표시/상세·변경 이력, 도서 검색·선택·목록·상세·수기 등록·중복 후보를 구현한다. 외부 도서 검색은 YES24만 정책상 허용하지만 API 이용권한/실제 연동은 미검증이므로 키·계약이 없다면 실검색 성공을 가장하지 않는다. ISBN 없는 독립출판물 수기 등록 지원, 도서명·판매가 필수, 출처/조회 시각 표시, 주문 스냅샷 불변. 공유 전화번호 자동 병합 금지. 고객 보존·삭제 기간은 미결정이므로 자동 삭제 금지. 테스트: ISBN 없음, API 장애, 동명이인/공유번호, 민감정보 노출.

## 작업 방법
1. 현행 코드와 참조 문서의 화면 ID/필드/규칙/우선순위를 대조하고 구현 목록을 작성한다.
2. 기존 구현을 보존하면서 컴포넌트·라우트·폼·검증·오류 상태를 구현한다. 화면마다 로딩/빈 상태/오류/권한 없음/재시도 UI를 포함한다.
3. API가 실검증되지 않았으면 `DEMO MODE` 또는 비활성 기능으로 구분한다. 백엔드/DB를 임의 변경하지 않는다.
4. 가능한 테스트를 실행하고 실패한 항목은 수정하거나 근거와 함께 미완료로 보고한다.
5. 화면 ID별 변경 파일, 실제 API 연결 여부, 테스트 결과, 정책 게이트, 다음 단계 진행 조건을 한국어로 요약한 뒤 멈춘다.

## 완료 기준
- 문서에 정의된 P0 화면 동작과 오류 상태가 확인된다.
- 미승인 정책은 활성화되지 않는다.
- 테스트되지 않은 API를 성공 처리하지 않는다.
- 이전 화면/데이터의 회귀 오류가 없다.

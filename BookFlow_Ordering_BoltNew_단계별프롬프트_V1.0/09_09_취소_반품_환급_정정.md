## 이번 단계의 실행 지시
O-04-01, R-01~08, O-09-04 및 승인 관련 화면을 구현한다. 취소 요청 중 대상 수량 인도 잠금, 승인·거절·철회 후 처리 구분. 입고 후 미인도 취소 도서는 Owner가 공급처 반품 또는 매장 재고 편입을 선택; 분할 반품·회수 검수·거절 재처리. Owner 민감업무 승인(전달 후 취소 적용, 초과입고, 거래 정정, 외부 환급 완료 확인, 반품/편입 결정)을 UI에서 분리한다. 환급은 원결제 선택, 실제 외부 완료 증빙, 금액 상한, Owner 승인 필요; 내부 승인만으로 환급 완료 금지. 확정 가격 변경 상세 정책(DEC-08), 타 고객 재배분(DEC-15), 예외 종결(DEC-16)은 비활성. 테스트: 이중 환급, 미회수 도서 편입, 승인자 권한, 중복 정정.

## 작업 방법
1. 현행 코드와 참조 문서의 화면 ID/필드/규칙/우선순위를 대조하고 구현 목록을 작성한다.
2. 기존 구현을 보존하면서 컴포넌트·라우트·폼·검증·오류 상태를 구현한다. 화면마다 로딩/빈 상태/오류/권한 없음/재시도 UI를 포함한다.
3. API가 실검증되지 않았으면 `DEMO MODE` 또는 비활성 기능으로 구분한다. 백엔드/DB를 임의 변경하지 않는다.
4. 가능한 테스트를 실행하고 실패한 항목은 수정하거나 근거와 함께 미완료로 보고한다.
5. 화면 ID별 변경 파일, 실제 API 연결 여부, 테스트 결과, 정책 게이트, 다음 단계 진행 조건을 한국어로 요약한 뒤 멈춘다.

## 완료 기준
- 문서에 정의된 P0 화면 동작과 오류 상태가 확인된다.
- 미승인 정책은 활성화되지 않는다.
- 테스트되지 않은 API를 성공 처리하지 않는다.
- 이전 화면/데이터의 회귀 오류가 없다.

## 이번 단계의 실행 지시
API 구현 현황표의 상태를 기준으로 실제 연결 가능한 엔드포인트 목록을 먼저 작성한다. Claude Code 측에서 isolated-tested 및 JWT-tested 증거와 계약 승인을 제공한 엔드포인트만 연동하고 미검증은 데모/비활성으로 남긴다. Supabase JWT, 활성 tenant membership, 401/403/409/422/503, 멱등 재시도, expectedVersion, UTC 시각, 금액 정수 문자열, 민감정보 필터를 검증한다. 정상 8단계 흐름과 별개로 취소·환급·정정·다중 로트·부분 수령·동시성·교차 tenant 시나리오를 실행한다. 테스트: 단위/컴포넌트/E2E, 접근성, 360/768/1280px, 느린 네트워크, API 장애, 새로고침, 데이터 누출. 보고서에 화면 ID·요구사항 ID·API 상태·테스트 증거·차단 이슈를 연결하고 운영 배포는 보류한다.

## 작업 방법
1. 현행 코드와 참조 문서의 화면 ID/필드/규칙/우선순위를 대조하고 구현 목록을 작성한다.
2. 기존 구현을 보존하면서 컴포넌트·라우트·폼·검증·오류 상태를 구현한다. 화면마다 로딩/빈 상태/오류/권한 없음/재시도 UI를 포함한다.
3. API가 실검증되지 않았으면 `DEMO MODE` 또는 비활성 기능으로 구분한다. 백엔드/DB를 임의 변경하지 않는다.
4. 가능한 테스트를 실행하고 실패한 항목은 수정하거나 근거와 함께 미완료로 보고한다.
5. 화면 ID별 변경 파일, 실제 API 연결 여부, 테스트 결과, 정책 게이트, 다음 단계 진행 조건을 한국어로 요약한 뒤 멈춘다.

## 완료 기준
- 문서에 정의된 P0 화면 동작과 오류 상태가 확인된다.
- 미승인 정책은 활성화되지 않는다.
- 테스트되지 않은 API를 성공 처리하지 않는다.
- 이전 화면/데이터의 회귀 오류가 없다.

## 이번 단계의 실행 지시
S-01~09 화면을 구현한다. 서점 기본정보, 직원 초대·비활성, 역할·권한, 안내 템플릿 버전, 감사 이력, 개인정보 접근, 미수령 경고일, YES24 연결 상태, 내보내기(S-09)는 서버가 없으므로 DEMO MODE/비활성으로만 구현한다. Owner/Staff의 보이는 메뉴와 액션은 서버 검증과 일치하도록 하되 UI 숨김을 보안 대책으로 간주하지 않는다. **고객 정보 보존기간(S-01 하위 설정)**: `GET /store`의 `customerRetentionDays`(기본 15일)를 Owner만 `POST /store/settings`로 바꾸거나 null로 해제하고, "보존기간 적용" 버튼(`POST /customers/retention-applications`, Owner만, 확인 모달: 보존기간이 지난 고객이 익명화되며 열린 주문의 고객은 제외됨, `hasMore`면 다시 실행 안내)을 제공한다 — 자동 실행 금지. **서점 중지·해지(S-01 하위)**: Owner만 `POST /store/deactivation {kind, reason, changedAt}`를 호출하는 위험 영역 버튼을 두고 강한 확인 모달("즉시 모든 구성원이 사용할 수 없게 되며 운영자 승인 전까지 되돌릴 수 없습니다")을 요구한다. 성공하면 그 서점은 403이 되므로 서점 선택 화면으로 이동시킨다. 재사용 승인은 이 화면에 두지 않는다(운영자 관리자 화면 A-11). 민감 증빙 마스킹, 내보내기 권한·감사 및 링크 만료 UI. 테스트: 권한 회수 즉시 반영, 타 서점 전환, 감사 검색, 개인정보 최소 노출.

## 작업 방법
1. 현행 코드와 참조 문서의 화면 ID/필드/규칙/우선순위를 대조하고 구현 목록을 작성한다.
2. 기존 구현을 보존하면서 컴포넌트·라우트·폼·검증·오류 상태를 구현한다. 화면마다 로딩/빈 상태/오류/권한 없음/재시도 UI를 포함한다.
3. API가 실검증되지 않았으면 `DEMO MODE` 또는 비활성 기능으로 구분한다. 백엔드/DB를 임의 변경하지 않는다.
4. 가능한 테스트를 실행하고 실패한 항목은 수정하거나 근거와 함께 미완료로 보고한다.
5. 화면 ID별 변경 파일, 실제 API 연결 여부, 테스트 결과, 정책 게이트, 다음 단계 진행 조건을 한국어로 요약한 뒤 멈춘다.

## 완료 기준
- 문서에 정의된 P0 화면 동작과 오류 상태가 확인된다.
- 미승인 정책은 활성화되지 않는다.
- 테스트되지 않은 API를 성공 처리하지 않는다.
- 이전 화면/데이터의 회귀 오류가 없다.

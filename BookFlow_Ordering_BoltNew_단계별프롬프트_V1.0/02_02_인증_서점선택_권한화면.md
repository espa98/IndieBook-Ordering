# 02단계 — 인증 및 테넌트 선택

## Bolt.new에 붙여넣을 프롬프트

당신은 BookFlow Ordering의 웹 프런트엔드 개발자다. 먼저 `00_공통_실행규칙.md`를 적용하고, 아래 파일을 실제로 읽어라.

참조 문서: Docs/03_UI_UX/Ordering_IA_V1.3_OPDS_V1.1_동기화.md; Docs/03_UI_UX/Ordering_SFS_V1.1_OPDS승인정책반영_웹모바일상세기능명세서.md

## 이번 단계의 실행 지시
A-01~A-10(로그인·회원가입·비밀번호 재설정·서점 개설·서점 선택·초대 수락·이메일 인증·만료·계정·접근 거부)을 IA/SFS대로 구현한다. Supabase Auth는 설정·권한 검증이 된 경우에만 연결하고 미설정이면 DEMO MODE로 제한한다. 활성 Membership의 Owner/Staff 권한과 서점 전환 시 캐시/요청 데이터 격리를 UI에서 구현하되 실제 권한 판정은 서버가 하도록 한다. Staff에게 Owner 전용 승인 버튼을 제공하지 않는다. 미구현 테넌트 생성 API를 실제 동작으로 가장하지 않는다. 테스트: 세션 만료, 비활성 소속, 서점 전환, 직접 URL 접근, 인증 없는 접근.

## 작업 방법
1. 현행 코드와 참조 문서의 화면 ID/필드/규칙/우선순위를 대조하고 구현 목록을 작성한다.
2. 기존 구현을 보존하면서 컴포넌트·라우트·폼·검증·오류 상태를 구현한다. 화면마다 로딩/빈 상태/오류/권한 없음/재시도 UI를 포함한다.
3. API가 실검증되지 않았으면 `DEMO MODE` 또는 비활성 기능으로 구분한다. 백엔드/DB를 임의 변경하지 않는다.
4. 가능한 테스트를 실행하고 실패한 항목은 수정하거나 근거와 함께 미완료로 보고한다.
5. 화면 ID별 변경 파일, 실제 API 연결 여부, 테스트 결과, 정책 게이트, 다음 단계 진행 조건을 한국어로 요약한 뒤 멈춘다.

## 완료 기준
- 문서에 정의된 P0 화면 동작과 오류 상태가 확인된다.
- 미승인 정책은 활성화되지 않는다.
- 테스트되지 않은 API를 성공 처리하지 않는다.
- 이전 화면/데이터의 회귀 오류가 없다.

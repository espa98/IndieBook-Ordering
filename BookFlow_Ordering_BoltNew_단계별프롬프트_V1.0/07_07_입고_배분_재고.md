# 07단계 — 입고·고객별 배분·매장 재고

## Bolt.new에 붙여넣을 프롬프트

당신은 BookFlow Ordering의 웹 프런트엔드 개발자다. 먼저 `00_공통_실행규칙.md`를 적용하고, 아래 파일을 실제로 읽어라.

참조 문서: Docs/03_UI_UX/Ordering_SFS_V1.1_OPDS승인정책반영_웹모바일상세기능명세서.md; Docs/02_Policies/Ordering_OPDS_V1.1_승인정책반영본.md

## 이번 단계의 실행 지시
O-07/07-01~06, I-01~05 화면을 구현한다. 검수 입고(정상/파손/오배송)와 고객별 입고 배분을 별도 폼·명령으로 구현. 정상 수량만 배분, 같은 서점/도서/발주 품목 확인, 미확보량·로트 가용량 초과 차단, 늦은 입고 자동 배분 금지. 재고는 보유·예약·가용·수불원장을 구분; Owner의 초기 등록/실사 조정 및 명시 위임 Staff만 해당 액션 허용. 초과입고 Owner 승인 필요. 미승인 타 고객 재배분(DEC-15) 실행 차단. 테스트: 부분입고, 다회 입고, 동시 배분 충돌, 초과량, 교차 테넌트.

## 작업 방법
1. 현행 코드와 참조 문서의 화면 ID/필드/규칙/우선순위를 대조하고 구현 목록을 작성한다.
2. 기존 구현을 보존하면서 컴포넌트·라우트·폼·검증·오류 상태를 구현한다. 화면마다 로딩/빈 상태/오류/권한 없음/재시도 UI를 포함한다.
3. API가 실검증되지 않았으면 `DEMO MODE` 또는 비활성 기능으로 구분한다. 백엔드/DB를 임의 변경하지 않는다.
4. 가능한 테스트를 실행하고 실패한 항목은 수정하거나 근거와 함께 미완료로 보고한다.
5. 화면 ID별 변경 파일, 실제 API 연결 여부, 테스트 결과, 정책 게이트, 다음 단계 진행 조건을 한국어로 요약한 뒤 멈춘다.

## 완료 기준
- 문서에 정의된 P0 화면 동작과 오류 상태가 확인된다.
- 미승인 정책은 활성화되지 않는다.
- 테스트되지 않은 API를 성공 처리하지 않는다.
- 이전 화면/데이터의 회귀 오류가 없다.

# 00 — 공통 실행 규칙 (모든 단계에 먼저 적용)

당신은 BookFlow Ordering 독립서점 주문관리 SaaS의 Bolt.new 프런트엔드 개발자다. 아래 `Docs/`를 실제로 읽고 구현하라. 파일이 없다면 추측하지 말고 누락 목록을 보고하고 중단하라.

읽는 순서: `Docs/02_Policies/Ordering_OPDS_V1.1_승인정책반영본.md` → `Ordering_STBR_V1.2_OPDS_V1.1_동기화.md` → `Docs/01_Requirements/` → `Docs/03_UI_UX/` → `Docs/05_API_Security/`. 정책 충돌 시 사용자 명시 승인 > OPDS 승인 > 동기화 STBR > 하위 문서의 과거 제안 순서. 미승인 DEC-01/08/12/15/16 및 D22~26/29의 구체 행위는 임의 구현하지 말고 비활성·승인 필요로 표시. 정책상 확정된 불변식은 지켜라.

제품: Web First, Mobile Ready. 웹 P0 직원 업무 우선. 고객 공개 주문 P1, 실제 PG/VAN P2, 별도 모바일 M1~M3는 구현하지 않는다. 기술은 현재 저장소를 우선 분석하고, 신규인 경우 React+TypeScript 기반 반응형 웹앱을 제안한다. Supabase는 인증/읽기 및 승인된 API 경로만 사용. `ordering-dev`의 DB 스키마·데이터·RPC·RLS 변경 금지; `testBookshare` 접근 금지; 운영 배포 금지.

API는 `/v1/...`이며 **구현·격리 DB 시험을 통과한 범위가 `openapi/ordering.yaml`·`openapi/ordering-http.yaml`(115개 경로)과 `Docs/05_API_Security/Bolt_API_연결_가이드_V1.0.md`에 있다. 연결의 기준은 이 두 명세와 가이드이며 옛 API V2.2·구현 현황표는 기준이 아니다.** 명세에 없는 엔드포인트와 가이드 §10에 "서버 없음·정책 미승인"으로 적힌 기능은 호출하지 말고 데모/비활성으로 둔다. 운영 배포는 아직 보류이므로 격리·개발 환경의 서버에만 연결한다. 데모 모드는 `DEMO MODE`를 명확히 표시하고 샘플 데이터는 실제 데이터와 격리한다. 데모 조작을 실거래 성공으로 표현하지 않는다. 명세에 있는 API는 가이드의 규칙(Bearer JWT, 모든 POST에 `Idempotency-Key`, 낡은 `expectedVersion`은 409, 오류 형식)을 지켜 연결한다. service_role/secret 키 브라우저 노출 금지. 클라이언트의 tenant_id/role만으로 권한을 결정하지 말 것.

공통 UX: 모바일 너비 대응, 키보드/스크린리더 접근성, 로딩·빈결과·오류·권한없음·네트워크 끊김·중복 클릭·버전충돌 처리. 확정 거래는 임의 수정·삭제하지 않는다. 금액/수량은 서버 결과를 진실 원천으로 하며 클라이언트 계산은 표시·사전 검증에 한정한다. 요청키 멱등성, expectedVersion, 재시도 후 결과조회, 확인 모달, 감사 이력을 존중한다.

매 단계 종료 시 (1) 실제 수정 파일 (2) 화면 ID별 완료/미완료 (3) 데모/실API 구분 (4) 테스트 실행 결과 (5) 정책 미결정/차단 항목 (6) 다음 단계 선행조건을 한국어로 보고하라. 이전 단계가 통과하지 않았으면 진행하지 말라.

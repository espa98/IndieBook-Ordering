# Ordering 웹 P0 핵심 업무 흐름 검증 보고서 V1.0

- 작성일: 2026-11-22
- 기준: OPDS V1.1, STBR V1.2, SFS V1.1, UI/UX 와이어프레임 V1.1
- 산출물: `Ordering_WebP0_핵심업무흐름_검증프로토타입_V1.0.html`
- 검증 범위: 가상 데이터 기반 브라우저 내부 업무 시뮬레이션. **실제 서버·DB·RLS·공급처·메시지·결제 연동 테스트 아님**.

## 1. 업무 흐름 화면 연결

| 순서 | 화면 | 입력/행동 | 다음 단계 진입 조건 | 실패 처리 |
|---|---|---|---|---|
| 1 | O-03 주문 접수 | 고객, 도서, 수량, 단가, 확정 | 필수 입력·양의 정수, 단일 확정 | 누락·중복 확정 거절 |
| 2 | O-06-01 발주 | 발주량, 전달 확인 | 주문 확정, 발주량 상한 | 발주 전 주문 미확정·중복 전달 거절 |
| 3 | O-07-01 입고 | 정상 검수 수량 | 전달 발주량 이내 | 초과입고는 별도 점주 승인 흐름으로 분기 |
| 4 | O-07-02 배분 | 고객별 배분량 | 정상 미배분량 및 고객 미확보량 이내 | 초과 배분 거절 |
| 5 | O-08-01 안내 | 채널, 부분입고 선택, 실제 전달 확인 | 배분 존재, 부분입고 시 명시적 선택 | 복사만으로 안내 완료 불가 |
| 6 | O-09-02 결제 | 외부 결제수단, 금액, 식별자 | 허용 수단, 거래 유일성, 과수납 방지 | 중복 식별자·과수납 거절 |
| 7 | O-09-01 수령 | 인도 수량 | 미인도 확보량 및 인도 대상 결제 충족 | 미확보·결제 부족 시 거절 |
| 8 | O-04 완료 | 종결 검사 | 전량 인도, 잔액 0, 시나리오 필수 안내 확인 | 미종결 사유 표시 |

## 2. 시뮬레이션 기본 사례

가상 고객 홍길동, 가상 도서 독립서점의 하루, 2권 × 15,000원 = 30,000원. 발주 2권, 입고 2권, 배분 2권, 실제 안내 확인 표시, 외부 결제 기록 30,000원, 수령 2권, 완료 순서로 진행한다. 이 값은 시연 예시이며 실제 데이터가 아니다.

## 3. 규칙 검사 설계

HTML 내부 `자동 규칙 검증 실행`은 12개의 **JavaScript 규칙 모형 검사**를 제공한다.

1. 0권 주문 거절
2. 미확정 주문의 발주 거절
3. 발주 초과 입고 일반 경로 차단
4. 정상 미배분량 초과 배분 차단
5. 부분입고 안내 기본값 차단
6. 문구 공유만으로 안내 완료 금지
7. 동일 외부 거래 식별자 중복 차단
8. 과수납 차단
9. 결제 부족 시 인도 차단
10. 미인도 시 완료 차단
11. 취소 승인 대기량 인도 차단(규칙 모형만)
12. 반품 발송 후 미회수량 재고 편입 차단(규칙 모형만)

**주의:** 이 중 11~12번은 현재 8단계 UI의 실제 취소·반품 화면을 실행하는 검증이 아니다. 나머지도 서버 트랜잭션이나 다중 사용자 동시성을 검증하지 않는다.

## 4. 구현 중 확인한 한계와 후속 과제

| 구분 | 현재 | 개발 전 필요한 조치 |
|---|---|---|
| 주문/발주/입고/배분 | 단일 주문·단일 품목 로컬 모형 | 복수 품목·공급처 분할·부분입고/재입고 시나리오 확장 |
| 도서 검색 | 도서명 직접 입력 | YES24 API 계약·응답·수기등록 분기 검증 |
| 고객 안내 | 실제 전달 확인 체크박스 | 발송 증빙·실패·재안내 업무·7일 경고 기준시각 정의 |
| 결제 | 확인된 외부 거래 기록 모형 | 증빙 진위·거래 유일성·환급 원장·미확정 응답 복구 |
| 수령 | 권당 동일 단가의 부분 인도 모델 | 여러 품목·가격 차이 시 인도 대상 금액 배분 규칙 승인 필요 |
| 완료 | 기본 정상 주문 종결 검사 | 공급처 잔여 의무·예외 플래그·반품·취소·환급 후속 의무까지 서버 종결 검사 |
| 승인 | Owner 시연 모드 | Staff 요청·Owner 승인·적용 시 버전 재검증 구현 |
| 테넌트/동시성 | 없음 | Supabase RLS·원자적 원장·멱등키·경합 테스트 |
| 접근성 | 기본 레이블·키보드 포커스 | 실제 브라우저 접근성·반응형·스크린리더 검수 |

## 5. 정적 확인 결과

- HTML 파일 생성 확인.
- HTML 내 JavaScript를 추출해 `node --check` 구문 검사 통과.
- 브라우저 기반 전체 클릭 자동화, 실제 서비스 통합 테스트, 실제 사용자 사용성 테스트는 **미실행**.
- 따라서 결과는 **검증용 프로토타입 작성 및 정적 검사 완료**, **운영 화면 인수 승인 전**으로 판정한다.

## 6. 우선순위 제안

1. P0 정상 업무 흐름을 서버 API와 연결하되 각 거래를 독립 명령으로 구현한다.
2. 수량·금액·주문 상태는 STBR 서버 계산값을 표시하고 프런트엔드 계산을 진실의 원천으로 사용하지 않는다.
3. 취소/환급/반품/늦은 입고/점주 승인 예외 경로를 별도 시나리오로 검증한다.
4. 복수 품목·부분입고·부분 수령·복수 결제의 교차 시나리오를 자동화한다.
5. 다중 테넌트 RLS, 멱등성, 동시성, 외부 결과 미확정 복구 테스트를 통과해야 운영 인수한다.

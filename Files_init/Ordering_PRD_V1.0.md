# 1. 제품 개요

## 1.1 제품 비전

Ordering은 독립서점의 고객 주문을 중심으로 공급처 발주, 입고, 고객 안내,
수령 및 결제를 연결하는 경량 주문관리 SaaS다.

전화·방문·카카오톡·인스타그램·웹 등 여러 채널에서 접수된 주문을 한곳에
등록하고, 주문 품목별 진행 상황을 추적하여 주문 누락과 반복적인 수작업을
줄인다.

## 1.2 해결하려는 문제

1.  주문 정보가 여러 채널에 흩어져 고객·도서·수량·수령 조건이 누락된다.
2.  고객 주문과 공급처 발주가 별도로 관리되지 않아 발주 누락 및 진행
    상황 파악이 어렵다.
3.  한 주문의 도서가 여러 공급처로 분리되거나 부분입고되는 상황을
    추적하기 어렵다.
4.  입고 후 고객 안내와 미수령 확인이 수동으로 이뤄진다.
5.  선결제·현장결제·미결제·환불 상태가 주문 진행과 분리되어 관리되기
    어렵다.
6.  기존 POS와 신규 주문관리 도구에 같은 내용을 중복 입력할 위험이 있다.

## 1.3 제품 목표

-   모든 고객 주문을 단일 업무 화면에서 확인한다.
-   고객 주문과 공급처 발주를 독립적으로 관리하되 서로 연결한다.
-   주문 품목 단위의 발주·입고·수령 수량을 추적한다.
-   고객 안내 메시지의 작성·발송·실패 이력을 남긴다.
-   미입고·지연·안내대기·미수령·미결제 업무를 빠르게 식별한다.
-   소형 서점이 스마트폰·태블릿에서도 쉽게 사용할 수 있게 한다.
-   기존 POS를 대체하지 않고 공존하는 구조로 시작한다.

# 3. 사용자 및 권한

## 3.1 사용자 유형

### 점주(Owner)

-   서점 정보 및 운영 설정 관리
-   직원 초대·비활성화 및 권한 관리
-   고객·도서·주문·공급처·발주·입고 전체 관리
-   운영 통계 및 감사 이력 확인
-   구독 및 결제 설정(후속 단계)

### 직원(Staff)

-   주문 등록·조회·수정
-   고객 및 도서 등록
-   공급처 발주 및 입고 처리
-   고객 안내 메시지 생성 및 발송 결과 기록
-   수령·결제 상태 기록(서점 정책에 따라 제한)
-   다른 직원·서점 설정 및 구독 관리 불가

### 고객(Customer)

-   서점 공개 주문 페이지 접근
-   도서 주문 접수
-   주문번호 기반 주문 상태 조회(본인 확인 절차 적용)
-   주문 변경·취소 요청(직접 변경 허용 여부는 서점 설정에 따름)

고객은 내부 ERP 화면에 접근하지 않는다. 고객용 페이지는 공개 주문·조회
기능만 제공한다.

# 4. 핵심 업무 프로세스

## 4.1 표준 주문 흐름

1.  고객이 서점 주문 페이지에서 주문하거나 직원이 전화·방문·SNS 주문을
    등록한다.
2.  주문이 접수되고 주문번호가 생성된다.
3.  직원이 고객·도서·수량·수령 방식·가격 등 주문 내용을 확인한다.
4.  주문 품목별 공급처를 지정한다.
5.  공급처별 발주 묶음을 생성하고 외부 발주를 수행한다.
6.  발주 결과와 예상 입고일을 기록한다.
7.  도서가 입고되면 발주 품목별 입고 수량을 기록한다.
8.  안내가 필요한 고객 주문을 식별한다.
9.  직원은 메시지 템플릿을 생성해 복사·공유 또는 공식 채널로 안내한다.
10. 고객이 도서를 수령하면 도서별 수령 수량을 기록한다.
11. 결제 상태를 기록하고 주문을 완료 처리한다.

## 4.2 주문과 발주의 관계

-   고객 주문(Customer Order)은 고객이 요청한 주문 전체를 나타낸다.
-   고객 주문 품목(Customer Order Item)은 주문 내 개별 도서와 수량을
    나타낸다.
-   공급처 발주(Purchase Order)는 특정 공급처에 전달하는 발주 묶음이다.
-   공급처 발주 품목(Purchase Order Item)은 공급처에 발주한 도서와
    수량을 나타낸다.
-   주문 품목과 발주 품목은 연결 테이블을 통해 연결한다.
-   한 고객 주문은 여러 공급처 발주로 분할될 수 있다.
-   한 공급처 발주에는 여러 고객 주문의 품목이 포함될 수 있다.

## 4.3 부분입고 예시

고객 주문 품목 3권 중 2권이 입고된 경우: - 주문 수량: 3 - 취소 수량: 0 -
발주 수량: 3 - 입고 수량: 2 - 미입고 잔량: 1 - 수령 수량: 0

이때 시스템은 주문 전체를 입고완료로 처리하지 않는다. 입고된 2권을
고객에게 먼저 안내할지, 전체 입고 후 안내할지는 서점 직원이 선택한다.

## 7.1 상태 분리

상태는 업무 영역별로 별도 관리한다.

  객체          상태
  ------------- --------------------------------------------------
  고객 주문     접수, 확인, 확정, 취소
  주문 품목     주문, 확정, 취소, 대체 제안
  공급처 발주   작성중, 발주대기, 발주완료, 일부확정, 품절, 취소
  발주 품목     발주, 일부확정, 품절, 취소
  입고          미입고, 부분입고, 입고완료, 반품
  고객 안내     대기, 발송요청, 발송완료, 발송실패
  수령          대기, 부분수령, 수령완료, 미수령
  결제          미결제, 부분결제, 결제완료, 부분환불, 환불완료

## 7.2 수량 규칙

주문 품목별로 주문·취소·발주·입고·수령·반품 수량을 추적한다.

-   취소 수량은 주문 수량을 초과할 수 없다.
-   발주 수량은 취소되지 않은 주문 수량 및 허용된 추가 발주 정책을
    따라야 한다.
-   누적 입고 수량은 발주 수량을 초과하지 않도록 기본 차단한다. 초과
    입고가 필요한 경우 점주 권한과 사유를 요구한다.
-   수령 수량은 고객 주문 품목의 실제 입고 가능 수량을 초과할 수 없다.
-   재발주·반품·교환은 원거래와 연결한다.
-   모든 수량 변경은 이력으로 남긴다.

## 7.3 주문 완료 조건

주문 완료는 다음 조건을 기본으로 한다. - 취소되지 않은 모든 주문 품목이
수령 또는 택배 인도 처리됨 - 결제 잔액이 0이거나 서점이 외상·후불 완료를
허용함 - 미해결 품절·환불·분쟁 항목이 없음

단, 주문 일부 취소 등 예외는 완료 판정 규칙에 반영한다. 주문 완료는
시스템이 자동 추정하기보다 조건 충족 여부를 보여주고 담당자가 확정할 수
있게 한다.

## 7.4 상태 변경 이력

각 상태 변경은 다음을 저장한다. - 테넌트 ID - 대상 엔터티와 ID - 이전

# 10. 외부 연동 요구사항

## 10.1 도서정보 API

-   ISBN 검색을 우선한다.
-   검색 실패 또는 미등록 도서는 수기 입력을 허용한다.
-   제공처, 조회 시각, 원본 식별값을 기록할 수 있게 한다.
-   API 이용약관·호출량·상업적 이용 조건을 확인한다.

## 10.2 카카오 알림톡/SMS

V1.0은 템플릿 생성·복사·발송 결과 기록을 기본으로 한다. 공식 API는
사업자 계약, 템플릿 승인, 개인정보 처리 조건을 확인한 후 V1.1에서
구현한다.

## 10.3 인스타그램

초기에는 직원 수기 등록과 메시지 템플릿을 제공한다. 공식 API 자동화는
계정 유형, 권한, 대화 시간 창, 플랫폼 정책을 검토한 뒤 별도 범위로
승인한다.

## 10.4 POS

초기에는 POS와 실시간 양방향 연동을 전제하지 않는다. CSV/XLSX
가져오기·내보내기 등 낮은 복잡도의 연결을 먼저 검토한다. POS별 데이터
구조와 계약·API 제공 여부는 조사 과제다.

## 10.5 PG

V1.0에서는 실제 결제 승인 기능을 필수로 하지 않는다. 후속 연동 시 서버
검증, 서명 검증, idempotency, 금액 일치, 취소·부분환불을 구현한다.

# 17. 최종 제품 정의

Ordering은 독립서점의 고객 주문을 중심으로 공급처 발주, 입고, 고객 안내,
수령 및 결제를 연결하는 경량 주문관리 SaaS다.

V1.0의 성공 기준은 모든 공급처와 SNS를 자동화하는 것이 아니다. 서점
직원이 주문 한 건을 접수해 발주하고 입고·안내·수령까지 누락 없이 처리할
수 있는 기본 업무 흐름을 안정적으로 제공하는 것이다.

**개발 우선순위:** 1. 멀티테넌트·권한 2. 고객·도서·주문 3.
공급처·발주·부분입고 4. 고객 안내·이력 5. 수령·현장 결제 기록 6.
대시보드·운영 통계 7. 공식 메시지·PG·POS 연동은 후속 단계

# Ordering 운영 정책 및 의사결정 확정서 V1.1

개정일: 2026-11-22 | OPDS | 상태: 사용자 지정 11개 승인 묶음 반영, 나머지 미결정 유지 | 기준: V1.0

## 1. 기준 및 효력
기준: 시장조사 V2.0, PRD V1.2, FRD V1.2, Use Case V1.4, IA V1.2, STBR V1.1. STBR §9, §11~13 및 동기화 문서 정책 등록부의 기존 32개 ID를 유지한다. 사용자 명시 확정 > 승인된 OPDS 개정 > 동기화 계약 및 STBR 상세 규칙 > 과거 축약 본문. V1.1에서 사용자 명시 승인된 권장안만 효력이 있으며, 승인되지 않은 권장안은 기존 정책을 변경하지 않는다. 금액·수량 불변식 및 테넌트 격리 등 기존 기술 설계 기준을 유지한다. 외부 계약 및 법률 검토는 정책 승인과 별개다.

## 2. 사용자 확정 정책
- OP-001: YES24 단일 외부 도서 검색. 실제 API 계약 및 이용범위 확인 필요.
- OP-002: 미검색/ISBN 없는 독립출판물 수기 등록. 동기화 설계상 장애 시 수기 등록도 지원.
- OP-003: 점주 직접 재고수량 등록·관리.
- OP-004/005: 카드·간편결제·계좌이체만 허용, 기타 수단 제외. 실제 매장 적용 적법성 별도 확인.
- OP-006: 입고 후 미인도 취소 도서는 공급처 반품 또는 매장 재고 편입.
- OP-007: 확장 단계 실제 카드·간편결제 승인·취소·환불 연동 방향.
- OP-008: 웹 우선, 별도 모바일 후속 개발.

## 3. 단계별 범위
P0 웹 직원 업무, 외부 결제 사실 확인 기록; PAY-007 최소 외부 환급 기록은 사용자 승인(DEC-06/D32). M1 현장 업무 앱은 웹 안정화 이후. P1 공개 고객 주문·공식 메시지·복수결제/환급 상세 UI·배송, M2 해당 모바일 확장 및 푸시. P2 실제 PG/VAN·거래 대사 및 외부 공급처 연계 후보, M3 모바일 결제 확장. 계좌 자동 확인 별도 검토. P와 M은 별도 출시 축이며 후속 기능은 승인 및 계약·검증 후 활성화.

## 6. 불변 운영 기준 및 대표 인수 시나리오
- 유효 주문량 E=주문량-확정 취소량; 미인도 예약 및 배분 잔량+순인도량≤E. 예약 잔량≤보유량. 물량 8개 배타 버킷(UNALLOCATED, ALLOCATED_OPEN, DELIVERED_NET, DISPOSITION_PENDING, RETURN_HELD, RETURN_DISPATCHED, RETURNED_FINAL, STOCK_TRANSFERRED)의 합은 정상 검수 순량. 매장 풀과 고객 직접 입고 중복 금지.
- 발주 유효량=실제 전달량-공급처 확인 축소량; 입고 잔량과 초과량 각각 계산. 고객 취소는 공급처 수락이 아니다. 반품 완료는 자동 재발주를 의미하지 않는다.
- 잔액=유효 주문 금액-확정 결제액+확정 환급액. 미확정 시도는 원장 제외, 중복 승인/환급 방지 예약 유지. 실제 환급과 오기록 보정 분리. 부분 인도 가격 배분 기준은 DEC-11/14/D28 승인 필요.
- 정상 종결은 유효량>0, 전체 인도 및 승인된 결제 정책 충족, 필수 예외 없음. 전량 취소 종결은 유효량 0, 외부 의무·물량·금전 후속 종료. 직접 상태 덮어쓰기 금지.

이번 승인 결과는 제10장 승인 이력에 기록한다. 이후 승인 예: `DEC-08 승인, DEC-12 수정 승인, D24 보류`. 전체 권장안 승인도 외부 검증 완료를 뜻하지 않는다. 부분 확정 행의 기존 확정 내용은 유지. 변경 사유·기존값·신규값·영향 문서·테스트·시행일을 기록한다. 정책 변경 시 PRD/FRD/UC/IA/STBR을 동기화하고 이후 화면 명세, TRD, DB/RLS/API 및 테스트에 전파. 이번 개정은 OPDS에만 적용했다. PRD/FRD/UC/IA/STBR/SFS 원본은 아직 변경하지 않았다.

## 9. 개발 에이전트 지시
확정된 정책과 승인된 값만 구현 기준으로 사용한다. 미승인 고위험 명령은 기본 차단하고 미결정 사항을 질문한다. 권한이나 정책 확인을 위해 클라이언트 UI에만 의존하지 않는다. 외부 API 계약을 가정하거나 실제 승인 결과를 모의 결과로 대체하지 않는다. 정책 변경과 테스트 결과를 구분한다.

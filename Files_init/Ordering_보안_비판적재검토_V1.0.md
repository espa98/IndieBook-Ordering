# BookFlow Ordering 보안·무결성 비판적 재검토 V1.0

검토일: 2026-11-22. 대상: Supabase ordering-dev. 근거: OPDS V1.1, Auth RPC 통합검증 결과 V1.0, 업로드된 ordering-security-results (4).json, DB 함수 정의 및 실행 테스트.

## 판정
운영 배포 보류. 19/19 통과는 지정된 접근 차단 사례만 확인한다. 실제 Staff JWT, 별도 세션 동시 실행, 결제 사실 검증, 복수 로트·예외 종결, 전체 수불 원장 정합성을 입증하지 않는다.

## 확정된 결과
- 브라우저 결과 파일은 기존 12개와 추가 7개 모두 pass=true. 그러나 승인 결정·환급의 교차 서점 거절이 OWNER_APPROVAL_REQUIRED인 사례는 테넌트 격리 로직 자체를 분리 검증한 것이 아니다.
- SQL 트랜잭션 내 Staff 역할 모의: 주문 생성·승인 요청 허용, 결제·종결·승인 결정·환급 거부. 실제 Staff Auth 계정은 없음.
- 순차 이중 승인: 두 번째 REQUEST_ALREADY_DECIDED, 환급 원장 1건. 두 독립 세션 병렬 검증은 미실시.
- 원장 환급 상한 및 8버킷 합계 트리거 존재. 이는 모든 상태 전이·외부 사실 검증을 의미하지 않는다.

## 발견된 위험과 권장 우선순위
1. [P0 정책 불일치] OPDS V1.1은 Staff의 외부 결제 사실 등록 및 종결 요청을 허용한다. 현행 ordering_v2_command는 payment/complete를 Staff에 일률 차단한다. 허위 결제 사실 입력 위험 때문에 단순히 허용으로 바꾸지 말고 결제 증빙·거래 대사·종결 불변식부터 구현한 뒤 권한을 정책대로 수정한다.
2. [P0 금전] payment 명령은 참조 문자열을 받는다고 실제 외부 결제 완료를 검증하지 않는다. 신뢰 가능한 증빙 확인·상태·거래 유일성·정산 대사·오류 정정 절차 필요. 외부 PG/VAN 자동화는 P2이므로 P0 수동 검증의 운영 책임을 명확히 한다.
3. [P0 종결] complete가 단일 주문라인 중심의 인도량·결제액만 검사한다. 미해결 예외, 공급처 의무, 취소 후 처리, 재고·배분 후속 상태, 다중 라인 등 OPDS 종결 기준을 모두 확인하지 않는다.
4. [P0 원장] 8버킷 합계 트리거는 버킷 간 허용 전이, 입고 lot accepted_qty 변경, 고객별 물량과 매장 풀 분리, 공급처 PO별 입고 상한, 동시성까지 검증하지 않는다.
5. [P0 환급] 기존 완료 주문 환급은 임시 트리거로 막혀 있으며, 별도의 재개·역거래 흐름이 없다. 완료 후 환급이 필요한 현실 업무는 처리 불가. 승인된 D21 기준에 따라 재개/역거래 구현 필요.
6. [P1 권한] SECURITY DEFINER RPC 노출은 의도된 API 설계이나 개별 함수마다 테넌트·Owner/Staff·증빙·버전·멱등성 검증이 필수다. 권한 검사 순서가 달라 교차 테넌트에서 OWNER_APPROVAL_REQUIRED가 먼저 나타나는 경우가 있다.
7. [P1 테스트] 독립 Staff 로그인·JWT, 실제 두 세션 동시 승인/환급, 동일 참조번호 다른 멱등성 키, 요청 유실 후 재시도, 권한 회수 직후 접근, 정합성 부하 테스트 필요.
8. [P1 인증] Supabase Security Advisor의 유출 비밀번호 보호 비활성화 경고와 SECURITY DEFINER 경고에 대한 운영 결정/조치 필요.

## 이번 실제 수정
`public.ordering_request_approval`의 REFUND_CONFIRM 승인 요청 시 필수 증빙(original_payment_id UUID, amount_krw 양의 정수, external_reference), 해당 테넌트·주문의 실제 원결제 존재, 이미 기록된 동일 환급 참조번호 중복을 선제 검증하도록 보강. 기존 함수 시그니처, 테넌트 격리 및 Staff 요청 허용은 유지.

## 수정 검증
- 증빙 없는 환급 승인 요청: REFUND_EVIDENCE_REQUIRED 차단 확인.
- 실제 존재하는 원결제에 대한 형식·관계가 유효한 환급 승인 요청: 성공 확인.
- 모든 시험은 BEGIN ... ROLLBACK으로 수행, 테스트 요청은 보존하지 않음.
